04 / 09

Gate

ban gaya
Generic — kyun

Har model ship karne layak nahi. Ek gate metrics check karke kharab model ko rok deta hai. Fail pe raise (return False nahi) — taaki CI ka exit non-zero ho aur pipeline ruk jaye.

Is project mein

Pure function: metrics dict andar → pass ya raise. Overfit gap < 0.15 (asli 0.0919), test R² > 0.85. Apna GateFailedError — taaki "gate ne roka" vs "code phata" alag dikhe.

Ye stage nahi — ye teen dhaage hain jo poore project ko bandhe rakhte hain: samajhne ke docs, liye gaye decisions, aur jaanbujh ke chhodi gayi kamzoriyan.

Decisions / ADR decisions

  • Ship 70%-fit vs refit 100% — pending ADR (mera vote: ship-70%)
  • ADR 0002 — no imputers, loudly fail karo
  • raise, return False nahi — CI non-zero exit
  • UTC no-colon + text latest.txt — Windows constraint

Jaanbujh ke kamzor risks

  • 🔴 gate.py/save.py ke koi test nahi — gate ka test milliseconds ka hai, likhna hi hai
  • 🟡 passed:True hardcode — call order pe bharosa, code pe nahi
  • 🟡 MAX_TEST_MAE=0.35 vs measured 0.3258 — sirf ~7% headroom (single split)
  • 🟡 Path(__file__).parents[3] — file ek folder sarki toh chupchaap galat jagah

Ek pending decision

Kaunsa model disk pe jaaye?

70%-fit model ship karein, ya 100% data pe refit karke?
Ship 70% (mera vote)
Jo model gate se pass hua aur jiske metrics metadata mein likhe hain — wahi disk pe jaaye. Metrics artifact ko sach mein describe karte hain. Traceability poori.
Refit 100%
Thoda behtar model milega, par metadata ke metrics ab ek alag model ke hain jise humne kabhi test hi nahi kiya. Metadata jhooth bolega.
→ Portfolio project ke liye traceability > thoda extra accuracy. Isliye ship-70%. Ye ADR mein likhna hai.
